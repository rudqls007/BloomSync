# Architecture

## 서비스 목표
BloomSync는 공통 백엔드를 중심으로 웹과 모바일 앱이 동일 데이터와 API를 사용하도록 설계합니다.

## 주요 원칙
- 데이터와 비즈니스 로직은 `backend/`에서 관리
- 공통 타입과 DTO는 `common/`에 정의
- 플랫폼별 UI는 `web/`과 `mobile/`에서 분리
- 클라이언트는 공통 API를 호출하여 동일 정보 조회

## 아키텍처 구성
- `backend/`
  - API 서버
  - 데이터 모델
  - 추천 로직
- `common/`
  - DTO
  - 타입 정의
  - 유틸리티 함수
- `web/`
  - 웹 UI 컴포넌트
  - API 호출 서비스
- `mobile/`
  - 모바일 UI 컴포넌트
  - API 호출 서비스

## 데이터/동기화 전략
- 공통 API를 통해 웹과 앱이 같은 데이터 소스를 조회
- 백엔드에서 데이터 변경 시 두 플랫폼은 API 재요청 또는 캐시 무효화를 통해 동기화
- 초기 MVP에서는 사용자 인증 없이 공개 데이터 중심으로 설계

## 확장 계획
- 로그인 / 사용자 맞춤 추천
- 위치 기반 구매처 추천
- 실시간 알림 및 즐겨찾기 동기화
